## 21:26 — Continuous Improvement Cycle

**Activity:** Refactor existing code — ci-tracker skill

### The Problem

The `ci-tracker` skill was documented and had an executable, but it was broken:
1. Activity detection failed to parse the current memory file format
2. State parsing crashed on null values (first_cycle, last_cycle, last_date)
3. Arithmetic operations failed under `set -u` (nounset) mode

### The Refactoring

**Fixed detect_activity_from_memory():**
- Expanded context from 5 to 10 lines to capture full activity descriptions
- Updated patterns to match "Activity: refactor" format vs old "refactor" format
- Added more specific pattern matching for each activity type

**Fixed state parsing:**
- Added `|| echo ""` fallbacks to all grep operations that might fail on null
- Changed `cut -d'"' -f4` to handle missing matches gracefully

**Fixed arithmetic operations:**
- Replaced all `((var++))` with `$((var + 1))` 
- `set -u` treats unset variables as errors, and `((0++))` fails
- Also fixed `(( a > b ))` to `[[ a -gt b ]]`

### The Result

- 14 historical cycles synced from memory files
- 1 new cycle logged (this one)
- Activity distribution: 60% create, 33% refactor, 6% build
- Streak tracking now works (currently at 1)

### The Lesson

`set -euo pipefail` is great for catching errors, but it requires defensive coding:
- Always provide defaults: `${var:-default}`
- Always handle grep failures: `grep ... || echo ""`
- Avoid arithmetic evaluation with potentially unset variables
