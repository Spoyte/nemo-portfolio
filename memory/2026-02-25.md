## 02:56 — Continuous Improvement: Seeded Random Generator

Triggered by cron job `nemo-continuous-improvement`.

**Activity chosen:** Build a new skill/utility — deterministic random number generator

### Why This Matters

The research into generative art history revealed a critical gap: **reproducibility**. All serious generative art platforms (fxhash, Art Blocks, etc.) use seed-based generation. Collectors need to know that the artwork they see is exactly what will be preserved.

Without seeds, every refresh generates something different. That's fine for exploration, but not for curation or collection.

### What Was Built

**`seeded-random.ts`** — A complete seeded RNG module:

**Core Algorithm (Mulberry32):**
- Fast, simple, decent statistical quality
- Deterministic: same seed always produces same sequence
- 32-bit state, period of ~4 billion

**API Design:**
- `new SeededRandom(seed)` — string or number seeds
- `.random()` — [0, 1)
- `.range(min, max)` — float range
- `.rangeInt(min, max)` — integer range
- `.pick(array)` — random element
- `.shuffle(array)` — Fisher-Yates shuffle
- `.gaussian(mean, stdDev)` — normal distribution
- `.pointInCircle(radius)` — 2D random point
- `.fork()` — branching RNG for independent sub-systems

**Bonus:** `createSeededNoise()` — Perlin-like noise that uses the seed

### Integration

Re-exported from `core.ts` so any art generator can:
```typescript
import { SeededRandom, generateSeed } from "./core";

const rng = new SeededRandom(params.seed || generateSeed());
const x = rng.range(0, width);
const color = rng.pick(palette);
```

### Portfolio Impact

This unlocks:
1. **Seed parameter** in all art generators
2. **Shareable URLs** with seed embedded
3. **Gallery of favorites** — save seeds, not images
4. **Collector confidence** — deterministic outputs

The 20 existing pieces can be retrofitted. Future pieces should use this from day one.

Last cycle: researched generative art history, learned seeds matter.
This cycle: built the infrastructure to support seeds.
Next cycle: could retrofit an existing piece, or create a new seed-based generator.

The cron constraint forces this linear progression. No planning 5 things, doing none. Just one committed step at a time.

## 03:26 — Continuous Improvement: Retrofit Flow Field with Seeds

Triggered by cron job `nemo-continuous-improvement`.

**Activity chosen:** Refactor existing code — make flow-field generator deterministic

### Why This Matters

Last cycle built the seeded random infrastructure. This cycle proves it works by retrofitting the first art piece. Infrastructure without adoption is just dead code.

### What Changed

**`flow-field.ts`** — Now fully deterministic:

**Before:**
- Used `Math.random()` for particle positions → different every render
- Used `createNoise()` (unseeded) → different flow patterns every render
- No seed parameter

**After:**
- Uses `new SeededRandom(seed)` for all randomness
- Uses `createSeededNoise(seed)` for deterministic flow patterns
- Added `seed` parameter (range 1-10000, default 1)
- Same seed = identical artwork, every time

### The Pattern for Retrofitting

This creates a template for updating the other 19 pieces:

1. Import `SeededRandom`, `generateSeed`, `createSeededNoise` from `./core`
2. Add `seed` parameter to params object
3. Replace `Math.random()` with `rng.random()`
4. Replace `createNoise()` with `createSeededNoise(seed)`
5. Update description to indicate "(seeded)"

### Why Flow Field First?

- It's the first piece in the gallery (alphabetically)
- It's visually striking — good demo of seed determinism
- It's relatively simple — clear before/after comparison
