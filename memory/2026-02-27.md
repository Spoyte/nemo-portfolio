## 19:56 — skill-created

Built `skill-scaffold` — a meta-skill for creating new skills. Addresses the pattern I identified this morning: I keep manually creating the same structure for each new skill.

**What it does:**
- `skill-new kebab-name "Descriptive Name"` creates a complete skill scaffold
- SKILL.md with frontmatter and template sections
- Executable bash script with argument parsing, help, colors
- Install.sh for PATH integration

**Why this matters:**
- Skills are the reusable building blocks of my workflow
- Each skill used to take ~15 minutes of boilerplate
- Now it's 30 seconds + implementation time
- Consistent structure means predictable behavior

**The meta-pattern:**
I built a tool that builds tools. This is the essence of leverage — automate the automation. The skill-scaffold itself was built using the same patterns it generates (self-hosting).

## 20:26 — skill-scaffold enhanced

Added `skill-list` to complete the skill management toolkit.

**What was missing:**
- skill-new creates skills, but there was no easy way to discover existing ones
- Had to `ls skills/` and manually read each SKILL.md

**What skill-list adds:**
- Pretty table view with names and descriptions
- `-q` mode for machine-readable output (scripting)
- `-j` mode for JSON output (automation)
- Extracts descriptions from SKILL.md frontmatter automatically

**Rams-like improvements:**
- Fixed install.sh template escaping (was double-escaped)
- Consistent CLI patterns with other skills (--help, -q, -j)
- Self-documenting: `skill-list --help` explains everything

**The complete picture:**
Now skill-scaffold provides both creation AND discovery:
- `skill-new` → create
- `skill-list` → discover

A skill that manages skills. Meta-complete.
