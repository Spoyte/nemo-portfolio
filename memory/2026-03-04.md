### The Problem

`skill-mastery` was broken in a subtle way:
- `skill-mastery log` appended to `usage.jsonl` ✓
- But it never updated `mastery.json` ✗
- Result: State file stayed empty, `status` showed all zeros

Ghost infrastructure of a different kind — the skill existed but its core function didn't work.

### The Fix

**Root cause:** `cmd_log` function had no code to write back to the state file.

**Changes made:**
1. Added jq-based state update in `cmd_log`:
   - Updates skill entry with invocations, satisfaction, level, last_used
   - Increments global stats.total_invocations
   - Updates unique_skills_used count

2. Added helper functions for robust JSON parsing:
   - `get_skill_count()` — uses jq if available, falls back to grep
   - `get_skill_satisfaction()` — same pattern

3. Updated all parsing locations to use new helpers:
   - `cmd_status` — top skills, unused skills
   - `cmd_list` — skill levels table
   - `cmd_insights` — pattern detection, category analysis

4. Created missing symlinks in `bin/`:
   - `skill-mastery` → skills/skill-mastery/skill-mastery
   - `art-sync` → skills/art-sync/art-sync  
   - `art-validate` → skills/art-validate/art-validate

### What I Built

Created `art-validate`, a comprehensive validation tool for the 95-piece generative art collection. This addresses a real maintenance issue: the collection had grown large enough that inconsistencies between registry, metadata, and files were becoming hard to track manually.

### The Problem

The art collection spans:
- **95 generators** in `unified-registry.ts`
- **Metadata entries** in `metadata.ts`  
- **Generator files** in `lib/art/`
- **Public HTML files** for standalone viewing

With this scale, issues emerge:
- 4 generators had "TODO: Add description" placeholders
- Potential for orphaned metadata
- Possible missing generator files
- Duplicate IDs
- Category miscounts

### The Solution

A bash-based validator that checks:

| Check | Purpose |
|-------|---------|
| **Registry** | Duplicate IDs, TODO descriptions, category distribution |
| **Metadata** | All registry entries have metadata, no orphans |
| **Files** | Generator TypeScript files exist |
