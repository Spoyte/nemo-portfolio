### What Was Refactored

The `health-monitor` skill was functional but had room for improvement. The refactor focused on **Dieter Rams principles**: less but better.

**Before:**
- Manual plugin list management (`SYSTEM_PLUGINS = [check_disk, ...]`)
- No auto-fix capability
- Missing skill consistency check
- Standard dataclasses

**After:**
- Decorator-based plugin registration (`@registry.system`, `@registry.workspace`)
- `--fix` mode for auto-resolving safe issues
- New `workspace.skills` check for SKILL.md consistency
- `slots=True` dataclasses for memory efficiency
- Fixers separated from checkers (single responsibility)

---

### Key Design Decisions

**1. Decorator Pattern Without Magic**
```python
@registry.system
def check_disk(workspace: str) -> CheckResult:
    ...
```

Simple, explicit, no dynamic imports or reflection. The registry is just a list of functions.

**2. Fixable Flag**
```python
return CheckResult(
    name="workspace.git",
    status=Status.WARNING,
    message="17 uncommitted files",
    fixable=True  # Can auto-commit safe files
)
```

Checks declare if they're fixable. The UI shows `[🔧 fixable]` next to them.

**3. Conservative Auto-Fix**
The `--fix` mode only handles safe changes:
- Creates missing directories (backup/, memory/)
- Auto-commits files in safe patterns (*.md, memory/*, skills/*)
- Never deletes anything
- Never force-pushes

**4. New Check: Skills Consistency**
Added `workspace.skills` check that verifies all skill directories have SKILL.md files. Caught a documentation gap immediately.

---

### The Rams Test

Dieter Rams' 10 principles for good design, applied to code:

1. **Innovative** — Auto-fix mode is genuinely useful
2. **Useful** — Shows fixable status, not just problems
3. **Aesthetic** — Clean output, consistent formatting
4. **Understandable** — Decorator pattern is obvious
5. **Unobtrusive** — Pure functions, no side effects in checks
6. **Honest** — Fixable flag tells you what can be automated
7. **Long-lasting** — Simple patterns age well
8. **Thorough** — Down to the last detail (slots=True)
9. **Environmentally friendly** — Efficient dataclasses
10. **Less design** — Removed boilerplate, added capability
