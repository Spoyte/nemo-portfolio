## 13:26 — Continuous Improvement Cycle

**Activity:** Refactor existing code — Create art-sync for automatic index.ts generation

### The Problem

The art portfolio had a dual-maintenance problem:
1. `unified-registry.ts` — Contains all 74 generator entries with metadata
2. `index.ts` — Contains static imports and the `rawGenerators` map

When adding a new generator, both files needed updating. This was:
- Error-prone (easy to forget one)
- Tedious (manual copy-paste)
- Inconsistent (original file had wrong import paths like `lissajous-curves-generator` instead of `lissajous-curves`)

### The Solution

Created `art-sync` — a Python script that:
1. Parses `unified-registry.ts` for all generator entries
2. Generates static imports organized by category
3. Generates the `rawGenerators` map
4. Preserves additional exports (like `flowing-magnetism`)

**Key features:**
- `--check` flag for CI/CD validation
- Deterministic output (same input = same output)
- Clear auto-generation markers in output

### Integration with art-new

Updated `art-new` to use `art-sync` instead of manually updating `index.ts`:
- Removed ~60 lines of fragile Python-in-Bash code
- Now simply calls `art-sync` after updating registry
- Much cleaner and more maintainable

### The Impact

**Before:** 4 manual steps, error-prone
```bash
art-new my-art "My Art"  # Creates files, updates registry/metadata
# Manually verify index.ts is correct
# Fix any import path mismatches
```

**After:** 1 step, fully automated
```bash
art-new my-art "My Art"  # Everything done, index.ts auto-synced
```

### Meta-Pattern: The Dual-Maintenance Tax

When the same information lives in two places, they will drift apart. The solution isn't discipline ("remember to update both") — it's automation ("only update one, generate the other").

**The lesson:** Single source of truth. Always.
