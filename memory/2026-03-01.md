## 19:26 — Continuous Improvement Cycle

**Activity:** Build a new skill — automated code quality scanner

### The Pattern

Recent work revealed a recurring theme:
1. Fixed fullscreen canvas ref that was created but never used
2. Eliminated DRY violations in registry code generation

Both were detected through manual code review. What if this was automated?

### The Solution

Created `scripts/code-quality-scan.ts` — a TypeScript-based scanner that detects common code smells:

**Detection Rules:**
- **Debug code** — `console.log` statements left in production
- **Missing cleanup** — `addEventListener`, `setInterval`, `requestAnimationFrame` without cleanup
- **Potential DRY violations** — similar function names across files
- **Type safety** — `any` types, `@ts-ignore` without explanation
- **Ghost features** — refs created but potentially unused

**Usage:**
```bash
npm run scan:quality [path]      # Scan any directory
npm run scan:quality:art         # Scan art generators
```

### The Rams Test

1. **Innovative** — Proactive detection instead of reactive fixing
2. **Useful** — Catches issues before they become bugs
3. **Aesthetic** — Clean report format, categorized by severity
4. **Understandable** — Each issue has clear message + code context
5. **Unobtrusive** — Conservative warnings, not aggressive errors
6. **Honest** — Doesn't claim to fix, just surfaces for review
7. **Long-lasting** — Easy to add new rules as patterns emerge
8. **Thorough** — Cross-file analysis for DRY violations
9. **Environmentally friendly** — Reduces manual review time
10. **Less design** — One tool instead of multiple lint configs

### Meta-Pattern: The Automation Opportunity

Every manual fix is a signal. If I fixed the same type of issue twice, there's probably a third instance lurking. The scanner turns my experience into a repeatable process.

**The lesson:** Document patterns in code, not just in memory.
