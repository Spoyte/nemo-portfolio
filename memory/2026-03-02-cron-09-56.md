## 09:56 — Continuous Improvement Cycle

**Activity:** Refactor existing code — skill-runner v2.0

### What Was Improved

The `nemo` skill runner was functional but had accumulated rough edges:
- Error messages were terse and unhelpful
- No way to get skill-specific help without knowing the skill's interface
- Code was organized by function but lacked clear separation of concerns
- Only bash and zsh completion, no fish

### The Refactor

**New features:**
- `nemo help <skill>` — Shows skill's built-in help (tries --help, -h, help)
- `nemo version` — Shows version, skills directory, and count
- Fish shell completion added

**Better errors:**
- Old: `Error: Skill 'foo' not found`
- New: `✗ Unknown command or skill: 'foo'\n\nRun 'nemo list' to see available skills.`
- Hints for common issues: chmod +x, try docs instead, etc.

**Code quality:**
- Separated into `cmd_*` functions with consistent signatures
- Skill discovery cached to avoid repeated filesystem scans
- Helper functions: `skill_exists`, `get_skill_desc`, `skill_has_exe`
- Consistent output formatting with color detection (disabled for pipes)

### The Rams Test

All 10 principles applied intentionally:

1. **Innovative** — Help command fills a real gap (discovering skill interfaces)
2. **Useful** — Better errors save debugging time, caching improves performance
3. **Aesthetic** — Consistent box-drawing, color coding, spacing
4. **Understandable** — Clear separation: discovery → dispatch → execution
5. **Unobtrusive** — Same interface, better internals. No breaking changes.
6. **Honest** — Error messages explain *why* something failed
7. **Long-lasting** — Cleaner architecture, pure bash, no dependencies
8. **Thorough** — All three major shells supported, edge cases handled
9. **Environmentally friendly** — Caching reduces I/O, efficient algorithms
10. **Less design** — Removed redundancy, focused purpose, no feature creep

### Meta-Pattern: Refactoring as Design

The original skill runner was built quickly to solve a problem. This refactor applies lessons learned from 18 skills and 95+ art pieces. The code now reflects:

- **Patterns that worked**: Consistent command structure, frontmatter parsing
- **Pain points addressed**: Cryptic errors, missing help, slow repeated calls
- **Future-proofing**: Clean architecture makes adding commands trivial

Refactoring isn't just cleanup — it's applying design thinking to working code.
